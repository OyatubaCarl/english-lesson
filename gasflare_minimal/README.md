これが動けば、あとは**記録する中身が増えるだけ**で、構造は変わらない。

```
gasflare_minimal/
  index.html        ← Cloudflare Pages に置く（ボタン・回数・同期状態。これ1枚で全部）

  gas/appsscript.json
```

サーバは無い。データベースも無い（スプレッドシートがデータベース）。費用はゼロ。

## 動かす手順

### 1. アプリ側（Cloudflare Pages）

```bash
cd gasflare_minimal
npx wrangler@latest pages deploy . --project-name=gasflare-minimal --branch=main --commit-dirty=true
```

出てきたURL（例 `https://gasflare-minimal.pages.dev/`）を控える。

この時点で開いても動く。ただし「記録していません」と出る。トークンが無いからだ。
**ボタンは押せるし、回数も数える。** GASが無くてもアプリは止まらない——これがこの設計の一線。

### 2. 記録側（スプレッドシート＋GAS）

1. **スプレッドシートを新規作成**する（何も書かなくていい）
2. **拡張機能 → Apps Script** を開き、`gas/コード.js` を「コード.gs」に貼り、
   「Dashboard.html」を新規作成して `gas/Dashboard.html` を貼る
3. **デプロイ → 新しいデプロイ → ウェブアプリ**
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
4. 出てきたウェブアプリのURLを**自分で一度開く** → サイトURLの入力フォームが出るので、
   手順1（アプリ側）のURLを貼る（「設定」シートに保存され、**シートをコピーしても引き継がれる**）
5. そのウェブアプリURLを生徒に配る

> このGASコードは**どのGASflareアプリでも共通**（学習アプリ3本と同一ファイル）。
> アプリ固有のタイトルや集計項目は、アプリが初回接続時に名乗る（マニフェスト方式）。

> ### ⚠ ここが唯一のワナ
> **「アクセスできるユーザー」を「全員」以外にすると、記録が一切残りません。**
>
> 「ドメイン内のユーザー」を選びたくなりますが、それでは**アプリからのPOSTが届きません**。
> 別オリジン（pages.dev）からの `fetch` にはクッキーが付かないので、GASは「誰か分からない」と判断して
> ログインページを返し、`doPost` が動かないからです。画面上は普通に遊べるのに、
> 「未同期」のまま数字が増えていく——という症状になります。
>
> **「全員」で安全です。** なりすましは署名トークンで止めています。署名の無いPOSTは全部捨てます。
> ブラウザで直接URLを開くときはクッキーが効くので、そこでドメイン判定ができます。
>
> スプレッドシートは必ず**「拡張機能 → Apps Script」から**開いて作ってください。
> 単体で作った Apps Script はどのシートにも紐づいておらず、書き込み先がありません。

### 3. 動かす

デプロイで出てきたウェブアプリのURLを、そのまま生徒に配る
（シートのメニュー **「GASflare」→「生徒に配るURLを表示」** でも確認できる）。

そのURLを、**学校のGoogleアカウントでログインした状態で開く**。
学校モードでは、シートの記録を読み込み終えるまでボタンは押せない（読み込み前に押すと数字が巻き戻って見えるため）。

アプリへ転送され、右下に「☁️ 同期済み」と出る。ボタンを押すと「未同期 +1」に変わり、
1.5秒後に送信されて「同期済み（14:03）」に戻る。スプレッドシートの「進捗」シートを見ると、
メールアドレスと回数が入っている。

### できるシート（すべて自動生成）

| シート | 中身 |
|---|---|
| **進捗** | 生徒（メール）× 項目。**先生が見るのはここ** |
| ログ | 出来事の生データ（このアプリでは未使用） |
| students | メール ↔ 不透明ID の対応表 |
| _data | 集計用（非表示） |
| _wallet | ログイン連続記録・スペシャルタコス・時間停止ライム（対応アプリ利用時のみ、非表示） |
| 設定 | サイトURL（コピーで引き継がれる） |
| **デプロイ管理** | 日時 / URL / Ver。**デプロイし直すたびに1行追記される** |

### デプロイ管理のしくみ

- **再デプロイでURLが変わると**、デプロイ管理シートに「日時・新URL・版数」が自動で追記される。
  いま配っているURLがどれか、いつ張り替えたかが履歴で追える
- **シートをコピーすると**、コピー先の初回アクセスで**前の先生のデータを自動で全消去**し、
  署名鍵も作り直す（前の先生が配ったURLのトークンは、コピー先には効かない）
- 判定はプロパティにキャッシュしてあり、通常アクセスではシートに触れない（生徒のPOSTを遅くしない）

## 「アクセスできるユーザー＝全員」でいい理由

アプリ（別オリジン）から `fetch` で POST するため。

クロスオリジンの `fetch` にはクッキーが付かず、GASは `Access-Control-Allow-Credentials` を返せない。
だから「ドメイン内限定」でデプロイすると、そもそも呼べない。

代わりに **HMAC署名トークン**で本人確認する。署名の無いPOST・壊れたPOSTは全部捨てるので、
URLを知られても他人になりすまして書き込むことはできない。

そして**ブラウザで直接URLを開くとき**は first-party なのでクッキーが効く。
そこで `Session.getActiveUser().getEmail()` が使える——これが次の話。

## 「学校のアカウントだけ」は、どこにも書いていない

`Session.getActiveUser().getEmail()` は、**スクリプトの所有者と同じドメインの利用者にしか、メールを返さない**。
他ドメインの人が開けば空文字が返るだけで、トークンが発行されない。

許可ドメインを書く設定は**どこにも無い**。他校の先生がこのシートをコピーすれば、
その瞬間から許可ドメインはその学校に切り替わる。誰も何も設定しない。

## メールはアプリへ渡さない

アプリが持つのは `stu_9f2c1ab77e40` のような**不透明ID**だけ。
それが誰なのかを知る手立てはアプリ側に存在しない。
メールとIDの対応表は、**先生のスプレッドシートの中にしかない**。

## 同期のタイミング

| 契機 | 動き |
|---|---|
| ボタンを押した | 1.5秒後に送る（連打は1回にまとめる） |
| 15秒ごと | 未同期があれば送る |
| タブを閉じる・裏に回す | `keepalive` を付けて即送信（ページが消えても送信は完走する） |
| 次に開いたとき | サーバの回数を読み込み、未同期分を送り直す |

「同期済み」と表示するのは、**GASが受け取った回数を返してきたときだけ**。
失敗した分は「未同期 +n」のまま残り、次の同期で必ず追いつく。

## ログインボーナスとアイテム

タコスパーティーは、GASflare接続時にログイン日・連続日数・自己ベスト・スペシャルタコス・
時間停止ライムを `_wallet` シートへ保存する。日付は端末時計ではなく、GAS側の日本時間を使う。

- 同じ学校アカウントなら端末を替えても同じ残高を読み込む
- 同日ログイン、同じレッスン報酬、同じ「続きから再開」をサーバー側で重複処理しない
- 通信できない間も学習は続けられるが、アイテムの付与・消費は接続回復後に確定する
- GASflareを使わない個人モードは、従来どおり端末内だけで記録する

`_wallet` は対応アプリから最初に利用されたとき自動生成される。古いGASコードのままの先生用コピーでは
アプリが端末内記録へ自動フォールバックするため、アカウント同期を有効にするには最新の
`gas/コード.js` を貼り直してウェブアプリを再デプロイする。

## 対応範囲について

前提は **1人1プロファイル**（Chromebookは自動的にそうなる。PCもプロファイル分離を推奨）。
この環境ではアカウントの取り違えは起きない。
マルチアカウント（家庭の共用ブラウザ等）で取り違えた場合は、
「アカウントを選んで開き直す」ボタンから学校のアカウントを選び直せる。
配るURLは、デプロイで出てきたものをそのまま使う。

## 他人の端末でログインしたら

localStorage は **Googleアカウントに紐づかない**（Chromeの同期対象外）。
友人の端末で同じChromeプロファイルからログインすると、友人の回数が自分のアカウントに合算されてしまう。

だから記録に**持ち主(sid)**を刻んでおき、違っていたら**アカウント側を正**として端末側の回数を捨てる。

> ただし、devtools で localStorage を直接書き換えるのは止められない。
> 回数の正本が端末にある以上、これは構造的に不可能。
> 止めているのは「借りてログインするだけで勝手に成立してしまう」casual な不正のほう。

## ここから先

記録する中身を増やしても、構造は変わらない。GAS側は**学習アプリ3本と完全に同一のファイル**なので、
やることはアプリ側で `entries`（項目ごとの進捗）とマニフェストを増やすことだけ。

- entries に項目を足す → 進捗シートの列が自動で生える
- manifest の stats を足す → ダッシュボードに集計列が生える
- `gasflare.log()` を呼ぶ → ログシートに出来事が時系列で残る

本人確認・署名・デプロイ管理は、このテンプレのまま1行も変えずに全アプリで使われている。
