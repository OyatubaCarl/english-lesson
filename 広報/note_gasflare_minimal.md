## 本文

### 前回のあらすじ

学習アプリを配っても、「誰がどこまでやったか」が分からなければ授業では使えません。かといって、一教員がサーバとデータベースを背負うのは無理です。

そこでこうしました。**アプリ本体は Cloudflare、学習記録は先生のスプレッドシート。**
先生はシートをコピーしてデプロイし、出てきたURLを配るだけ。そのURLを踏んだ生徒の記録だけが、その先生のシートに溜まっていきます。

この組み合わせを **GASflare**（GAS ＋ Cloudflare）と呼んでいます。

今回は、その**骨格だけを取り出した最小実装**を、全部見せます。

### 作るもの

**ボタンが1つ。押した回数を表示するテキストボックスが1つ。同期の状態が1行。**

それだけです。

デモ → https://gasflare-minimal.pages.dev/

いま開くと「記録していません」と出ます。トークンが無いからです。それでも**ボタンは押せるし、回数も数えます**。GASが無くてもアプリは止まらない——これはこの設計で絶対に譲らない一線です。

先生のURLから開くと、右下が「☁️ 同期済み（14:03）」に変わります。ボタンを押すと「未同期 +1」になり、1.5秒後に送信されて「同期済み」に戻る。スプレッドシートを見ると、メールアドレスと回数が入っています。

ファイルは2枚だけです。

```
index.html      ← Cloudflare Pages に置く（ボタン・回数・同期状態。これ1枚で全部）
gas/コード.js    ← 先生のスプレッドシートに貼る（本人確認・署名・書き込み。これ1枚で全部）
```

サーバはありません。データベースもありません（スプレッドシートがデータベースです）。費用はゼロです。

### 流れ

```
生徒 ──(ブラウザで先生のGAS URLを開く)──▶ 先生のGAS
                                          Session.getActiveUser() でメールを取る
                                          メール → 不透明ID (stu_xxxx) に変換
                                          {sid, url, exp} を HMAC 署名
                                             │
        ?tt=<署名トークン> を付けて転送 ◀────┘
             │
             ▼
      ボタンのページ (Cloudflare Pages)
             │  押した回数を、トークンに書かれた「その先生のGAS」へ POST
             ▼
      先生のGAS ──(署名を検証 → sid確定)──▶ 先生のスプレッドシート
```

### 「学校のアカウントだけ」は、どこにも書いていない

生徒が先生のURLを開くと、Apps Script はこう書いてあるだけです。

```js
function activeEmail_() {
  try { return String(Session.getActiveUser().getEmail() || '').toLowerCase(); }
  catch (e) { return ''; }
}
```

この API には、こういう性質があります。

> **スクリプトの所有者と同じドメインの利用者にしか、メールを返さない。**

他ドメインの人が開けば、空文字が返るだけ。トークンは発行されません。

つまり **「学校のアカウントのみ」という制限は、設定ではなく Google の仕様そのもので成立している**わけです。許可ドメインを書く設定ファイルは、どこにもありません。他校の先生がこのシートをコピーすれば、その瞬間から許可ドメインはその学校に切り替わります。誰も何も設定しない。

### 渡すのは、改ざんできない名札

メールが取れたら、不透明なIDに変換して、署名付きのトークンを作ります。

```js
function sign_(payload) {
  var p = b64_(JSON.stringify(payload));
  return p + '.' + b64_(Utilities.computeHmacSha256Signature(p, key_()));
}
```

トークンの中身は3つだけです。

- **誰か** — メールではなく `stu_9f2c1ab77e40` のような不透明なID
- **どこへ送り返すか** — その先生の Apps Script のURL
- **期限**

鍵は、その Apps Script が初回に自分で作った乱数です。**アプリにも通信路にも一切出てきません。**

だからIDを書き換えれば署名が合わなくなって捨てられますし、送り先も署名の中にあるので、他人のGASへ差し替えることもできません。

### メールは、シートの外へ出ない

アプリが持つのは**不透明IDだけ**です。それが誰なのかを知る手立ては、アプリ側に存在しません。メールとIDの対応表は、**先生のスプレッドシートの中にしかない**。

先生が見るシートには、照合済みのメールが並びます。**先生には見える。アプリには見えない。**

### クッキーの効かない場所で、どうやって名乗るか

ここが技術的な山場です。

ボタンのページは `pages.dev`、GAS は `script.google.com`。**別のオリジンです。** ブラウザはクロスオリジンの `fetch` にクッキーを付けません。付けようとしても、GAS は `Access-Control-Allow-Credentials` を返せないので、ブラウザが拒否します。

つまり、**記録を送る瞬間、GASは「誰が来たのか」をGoogleのセッションからは知りようがない。**

だから、さっきの署名トークンで名乗ります。これがこの設計の核心です。

```js
fetch(claims.url, {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain;charset=utf-8' },  // ← ここが肝
  body: JSON.stringify({ action: 'record', tt: token, count: n }),
});
```

**`text/plain` にしている理由。** `application/json` にすると CORS のプリフライト（OPTIONS）が飛びます。GAS は `doGet` と `doPost` しか持たず、OPTIONS に答えられません——必ず失敗します。`text/plain` は「単純リクエスト」に分類されてプリフライトが飛ばない。**これが唯一の通し方です。** 中身はJSON文字列なので、GAS側は普通にパースできます。

副作用として、クッキーを一切使わないので **CSRF が原理的に成立しません。**

### 同期のタイミングと、「同期済み」の意味

| 契機 | 動き |
|---|---|
| ボタンを押した | 1.5秒後に送る（連打は1回にまとめる） |
| 15秒ごと | 未同期があれば送る |
| タブを閉じる・裏に回す | `keepalive` を付けて即送信（ページが消えても送信は完走する） |
| 次に開いたとき | サーバの回数を読み込み、未同期分を送り直す |

大事なのは、**「同期済み」と表示するのは、GASが受け取った回数を返してきたときだけ**という点です。

```js
if (r && r.ok) {
  localStorage.setItem(K_SENT, String(Math.max(sent(), Number(r.count) || 0)));
}
```

失敗した分は「未同期 +3」のまま残り、次の同期で必ず追いつきます。**送ったつもり、を作らない。** これだけで、通信が切れても、GASが一時的に落ちても、記録は取りこぼされません。

### 記録に残るのは、GASflareのURLから入った分だけ

最後に、いちばん考えさせられたところを書きます。

**localStorage は、Googleアカウントに紐づきません。** Chrome の同期対象外で、オリジン × ブラウザプロファイルに属します。

これは何を意味するか。**「端末に記録がある」ことは、「その人がやった」ことを意味しない。** 友人の端末かもしれないし、ログイン前に誰かが遊んだ分かもしれない。

素朴に「ローカルの記録とサーバの記録をマージする」実装にすると、**友人の端末を借りてログインするだけで、友人の成果が自分のアカウントに合算されます。** これは実際に成立してしまう不正でした。

なので、こうしました。記録に**持ち主（sid）**を刻んでおき、

- 持ち主 = いまログインしている生徒 → 学校モードで貯めた分。そのまま送る（オフラインで進めた分も届く）
- **持ち主 ≠ いまログインしている生徒 → アカウント側の記録が正。端末の記録は捨てて、サーバから読み直す**

**端末の記録がアカウントへ合流する経路は、用意しません。** 記録に残るのは、**先生のURLから入って学習した分だけ**。それが正道だと思います。

### 「絶対に安全」ではない、とは書いておきます

止められない不正もあります。全部書きます。

**devtools で localStorage を書き換える。** 回数の正本が端末にある以上、これは構造的に防げません。どんなクライアント主導の設計でも同じです。

**自分のGoogleアカウントを友人に貸して、代わりにやってもらう。** これはどんなシステムでも防げません。本人が鍵を渡しているので。

**先生のURLを他クラスの生徒に横流しする。** 同じ学校のドメインなら入場できてしまいます。先生のシートに知らない名前が並ぶだけなので実害は小さいですが、起こりえます。

止められるのは、**「他人になりすます」ことと、「他人の記録が勝手に自分に混ざる」こと**です。逆に言えば、**「本人が、自分のアカウントで、嘘の数字を送る」ことは防げません。**

だから、私はこう考えています。**この記録を、そのまま成績にしない。** 取り組みを可視化するための道具として使う。誰がやっていて誰がやっていないかが分かるだけで、声かけの精度はまるで変わります。それで十分だと思っています。
